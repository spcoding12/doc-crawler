## 2024-06-12 - [Performance Pattern: BeautifulSoup HTML Parsing]
**Learning:** Extracting simple tags or attributes (e.g., framework fingerprints) is significantly faster by executing sequential `soup.find()` or `soup.find_all()` lookups rather than iterating over an array of slow `soup.select()` CSS selector matches. Furthermore, serializing tags with `str(tag)` incurs a massive performance penalty; using `.text` and explicitly evaluating `.get('src', '')` provides exactly equivalent capability with >10x speed improvement. Consolidating independent class checks into `class_=['a', 'b']` is an optimized OR check and traverses the tree once. Placing early returns (e.g. metadata string checks) *before* heavy DOM traversals yields substantial speedup for non-matching inputs.
**Action:** Always prefer direct DOM lookup methods (`find`, `find_all`) with specific attribute or class matchers over generic CSS selector execution (`select`), especially when iterating over potentially huge parsed structures. Do not stringify BeautifulSoup objects via `str(tag)` for basic existence checking; rely solely on native tree node properties. Evaluate explicit tag data before generic class structures.
