## 2024-05-18 - BeautifulSoup CSS Parsing Overhead
**Learning:** Using `.select()` with CSS selectors inside loops for framework detection incurs significant parsing overhead and slows down detection by over 95% compared to direct traversal using `.find()` with `kwargs`. Furthermore, `.select()` searches for all matching instances whereas `.find()` short-circuits on the first match.
**Action:** Always prefer direct attribute lookups (e.g., `{'class_': '...'}, {'name': '...', 'attrs': {...}}`) with `.find()` over CSS selector strings with `.select()` when processing parsed HTML trees, especially in frequently called detection or traversal logic.
## 2024-05-18 - Safe BeautifulSoup CSS Query Replacement
**Learning:** While replacing `.select()` with direct attribute lookups avoids heavy CSS parsing overhead, it is critical to replace it with `.find_all()` instead of `.find()` when iterating over results. `.select()` returns a list of *all* matches, whereas `.find()` short-circuits on the *first* match. Replacing a list generator with a single-element fetch introduces severe functional regressions if the condition requires evaluating multiple identical tags (e.g., checking multiple `<script>` tags for a specific keyword).
**Action:** When optimizing away `.select()` inside loops that expect to evaluate multiple candidate tags, always use `.find_all(**kwargs)` to maintain functional correctness, or use `.find()` with a custom filter lambda if you specifically want to short-circuit the entire list search efficiently.
