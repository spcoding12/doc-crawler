## 2024-05-24 - Avoid `.select()` in BeautifulSoup for simple lookups
**Learning:** In BeautifulSoup, using CSS selectors via `.select()` (which delegates to SoupSieve) is significantly slower than using native `.find()` or `.find_all()` with specific attributes or `class_` lists, due to the parsing overhead of the selector string. Consolidating multiple `class` checks into a single `.find(class_=['a', 'b'])` avoids repeated tree traversals. Additionally, when replacing `str(tag)` with `.string`, always remember to explicitly check attributes (like `src`) if the original logic relied on stringifying the entire tag, otherwise you introduce regressions (like missing scripts loaded via `src`).
**Action:** When optimizing HTML parsing bottlenecks, aggressively replace `.select()` with `.find()` and consolidate repetitive DOM walks. Pay strict attention to the semantics of tag text (`.string`, `.text`) versus attributes when replacing raw stringification (`str(tag)`).
