## 2025-02-18 - Optimized framework detection logic in detector.py
**Learning:** Checking for specific HTML elements and attributes iteratively using `.select()` can be inefficient because `.select()` involves overhead from parsing CSS selectors and navigating the DOM tree repeatedly. Furthermore, the early existence checks (e.g., checking for classes) were causing skips over more specific data extraction (e.g., getting version strings from `<meta>` tags) if they happened first.
**Action:** When optimizing sequential detection logic (like framework identification), ensure that operations extracting specific data (e.g., version strings from `<meta>` tags) are evaluated before fallback early-return existence checks (e.g., matching a generic class name). Placing early returns first causes the specific data extraction to be unintentionally skipped if the early condition is met. Consolidate multiple independent class checks into a single-pass operation by passing a list to the class parameter (e.g., `soup.find(class_=['class1', 'class2', ...])`). Use `.find()` or `.find_all()` with direct attribute lookups instead of `.select()` with CSS selectors to avoid parsing overhead.
