
## 2024-05-24 - Optimizing BeautifulSoup Lookups in DOM Detection
**Learning:** In `src/detector.py`, the original implementation iterates over arrays of `selector` tuples using `soup.select(selector)`. This involves invoking the CSS selector engine which has higher overhead than native `find` or `find_all` methods. For simple attribute (e.g., `meta[name="generator"]`) or class (`.classname`) checks, direct lookups using `soup.find` or `soup.find(class_=[...])` are significantly faster. In fallback scenarios or deep checking (like "unknown" frameworks where all checks miss), replacing `select` calls and evaluating simple tag attributes earlier speeds up execution by over 2x (e.g. from 3.77s to 1.66s for 500 iterations). Avoid `str(tag)` on elements with many children like scripts, as it forces tree serialization; use `.text` which is much faster.
**Action:** Replace `soup.select()` with targeted `soup.find()` or `soup.find_all()`. Consolidate multiple individual class existence checks into a single `soup.find(class_=['class1', 'class2', ...])` to take advantage of BeautifulSoup's fast short-circuiting list match. Fast-path specific metadata checks (like `meta[name="generator"]`) before generic script or deep DOM searches.
